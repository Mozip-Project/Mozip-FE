# 시각 검증 규칙

Figma 기준과 실제 렌더 결과를 비교할 때는 눈에 띄는 차이보다 사용자가 읽고, 이해하고, 조작하는 흐름에 영향을 주는 차이를 우선합니다.

## 검증 입력

- 대상 Figma node URL과 해당 frame의 크기 또는 확인 가능한 화면 근거
- 실제 route 또는 section의 렌더 화면
- 확인에 사용한 viewport와 관련 diff

Figma와 렌더 화면이 모두 있어야 시각적 일치 여부를 판정합니다. 하나가 없으면 통과로 표현하지 않고, 없는 입력과 코드 수준에서 확인한 범위를 분리해 보고합니다.

## 비교 순서

1. 섹션 순서, 정보 위계, 핵심 CTA, 이미지·카피의 존재와 배치를 확인합니다.
2. 컨테이너 폭, 여백 리듬, grid, 정렬, 텍스트 줄바꿈처럼 읽기 흐름에 영향을 주는 요소를 비교합니다.
3. 작은 화면에서 가로 overflow, 잘림, 겹침, 터치 대상, 키보드 흐름을 확인합니다.
4. 모션은 Figma 또는 사용자 자료에 근거가 있을 때만 비교하고, `prefers-reduced-motion`에서도 콘텐츠와 조작이 남는지 확인합니다.

Figma frame 크기를 알 수 있으면 그 크기를 우선 사용합니다. 모바일 디자인이 제공되지 않았다면 임의의 모바일 완성도를 주장하지 않고, 확인한 좁은 viewport와 남은 공백을 기록합니다.

## 수정이 필요한 차이

다음은 `NEEDS_REVISION`으로 보고합니다.

- 섹션·핵심 정보·CTA가 누락되었거나 순서가 바뀌어 이해 흐름이 달라진 경우
- 콘텐츠가 잘리거나 가로로 넘치고, 서로 겹치거나 조작할 수 없는 경우
- 제목·본문의 밀도, 정렬, 자산 선택이 브랜드 메시지나 정보 위계를 실질적으로 바꾸는 경우
- 근거 없는 사업 실적·성능 인상을 주는 이미지나 카피가 추가된 경우
- 필수 모션이 콘텐츠 접근을 막거나 reduced motion에서 대체 흐름이 없는 경우

안티앨리어싱, 서브픽셀, 운영체제 글꼴 렌더링, 동적 브라우저 UI에서 생긴 미세한 차이와 근거 없는 취향 평가는 결함으로 기록하지 않습니다.

## 증거와 보고

- 비교 결과는 Figma node, route 또는 section, viewport, 사용한 화면 근거를 함께 남깁니다.
- 발견 사항은 심각도, 차이, 사용자 영향, 최소 수정 방향 순서로 작성합니다.
- 임시 캡처와 비교 산출물은 요청받지 않는 한 저장소에 추가하지 않습니다.
- 독립 검토가 필요한 경우 `.claude/agents/visual-verifier.md`에 같은 입력을 전달합니다.
