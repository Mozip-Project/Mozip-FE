# 프로젝트 제약 조건

## 범위

- MOZIP.은 지원자와 운영진이 같은 모집 데이터를 다루는 통합 모집 플랫폼입니다. 기능 범위와 사용자 흐름은 `.claude/references/product-brief.md`를 기준으로 합니다.
- product-brief의 "미정 사항"(AI 기능 범위, PRO 경계 등)에 해당하는 기능은 확정된 것처럼 구현하지 않고, 필요하면 범위를 먼저 확인합니다.
- 지원자 화면과 운영진 화면은 권한과 레이아웃이 다릅니다. 한쪽 화면을 바꿀 때 같은 데이터를 쓰는 다른 쪽 화면이 영향을 받는지 확인합니다.
- 버튼·폼·링크는 확인된 목적지나 API가 있을 때만 실제 동작으로 연결합니다. 없으면 연결이 필요하다고 보고합니다.

## 미결정 사항

- `docs/ARCHITECTURE.md`에 정해지지 않은 구조(도메인 코드 폴더·이름, 운영진 URL, 계정 구분)는 팀이 결정합니다. 작업에 필요하면 임의로 정하지 않고 결정이 필요하다고 먼저 알립니다.
- 팀이 결정한 내용은 `.claude/decisions/records/`에 기록하고 `docs/ARCHITECTURE.md`에 반영합니다.

## 사실과 콘텐츠

- 화면 문구의 근거는 `.claude/references/product-brief.md`와 Figma입니다.
- 확정되지 않은 수치, 가격, 일정, 제휴, AI 성능을 사실처럼 만들지 않습니다. 빈칸은 임의의 마케팅 문구로 채우지 않고 확인을 요청합니다.
- 지원서, 프로필, 면접 기록은 개인정보입니다. 예시·테스트 데이터에 실제 사람의 정보를 쓰지 않습니다.

## 기술

- `pnpm`만 사용합니다.
- Next.js App Router와 Tailwind CSS v4를 유지합니다. Tailwind v3 설정 파일이나 Vite/React Router 전용 설정을 추가하지 않습니다.
- production dependency는 명시 요청 없이는 추가하지 않습니다.
- 외부 이미지 호스트, 분석 스크립트, 폰트, iframe은 개인정보·성능·운영 소유자가 확인된 경우에만 추가합니다.

## 디자인

- 디자인 근거는 `.claude/references/design-source.md`의 Figma입니다. 확정된 레이아웃·문구·에셋을 우선하고, 부족한 내용은 추측으로 채우지 않습니다.
- Figma에 없는 화면 상태(빈 목록, 로딩, 에러, 모바일)는 디자이너에게 확인할 항목으로 보고합니다.
- 외부 서비스(동들, 나인하이어 등)는 정보 구조 참고만 하며 UI·문구를 복제하지 않습니다.
