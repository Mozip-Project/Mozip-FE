# 랜딩 UI와 접근성

## 콘텐츠와 구조

- `.claude/references/design-source.md`의 Figma 노드와 IA를 기준으로 섹션의 순서와 메시지를 유지합니다.
- 한 화면에서 가장 먼저 읽혀야 할 메시지, 보조 설명, CTA의 위계를 Figma와 콘텐츠 근거에 맞춰 유지합니다.
- 제목을 시각적으로 작게 보이게 하더라도 heading 계층은 정보 구조에 맞게 작성합니다. 장식 문구를 heading으로 만들지 않습니다.
- 외부 링크는 새 탭이 필요한 이유가 있을 때만 `target="_blank"`를 사용하고, 사용자가 이동 결과를 예측할 수 있는 라벨을 제공합니다.
- CTA, 이메일, 전화번호, 문의 링크는 제공된 목적지 또는 확인된 연락 수단이 있을 때만 연결합니다.

## 접근성과 이미지

- 데스크톱만 맞추지 않습니다. 좁은 화면에서 가로 스크롤, 잘린 제목, 터치 불가능한 컨트롤이 없어야 합니다.
- 의미에 맞는 `header`, `main`, `section`, `nav`, `footer`, `button`, `a`를 사용합니다.
- 페이지 전체에는 목적이 분명한 `h1` 하나를 두고, 섹션 제목은 순서가 이어지는 heading 계층으로 작성합니다.
- 장식 이미지는 빈 alt, 정보를 전달하는 이미지는 구체적인 alt를 제공합니다.
- 키보드 포커스가 보이고, 링크와 버튼의 목적이 텍스트 또는 접근 가능한 이름으로 드러나야 합니다.
- 색상만으로 상태를 전달하지 않고, 충분한 대비와 텍스트·아이콘 보조를 제공합니다.
- 키보드로 도달하는 요소의 focus 순서는 화면의 읽기·조작 순서와 일치해야 합니다.
- 이미지와 영상은 실제 사업 활동·실적으로 오인되지 않도록 캡션 또는 문맥을 검토합니다. `.claude/references/product-brief.md`의 콘텐츠 주의 사항을 함께 확인합니다.
- Hero 등 첫 화면의 핵심 이미지만 우선 로드를 검토하고, 화면 밖 장식 이미지는 기본 지연 로딩을 유지합니다.
- 이미지 영역은 고정된 크기·비율 또는 `fill`과 올바른 `sizes`를 지정해 CLS를 방지합니다.

## 상호작용 상태

- hover만으로 중요한 정보나 조작을 제공하지 않습니다. 키보드 focus와 터치 환경에서도 같은 목적을 달성할 수 있어야 합니다.
- 메뉴, accordion, carousel처럼 상태가 있는 UI는 열림·닫힘 상태와 현재 항목을 접근 가능한 방식으로 드러냅니다.
- 링크와 버튼은 목적에 따라 구분합니다. 페이지·섹션 이동은 `a`, 현재 화면의 동작은 `button`을 사용합니다.

## 반응형 확인 순서

1. 작은 화면에서 내용이 한 열로 자연스럽게 읽히는지 확인합니다.
2. 제목·숫자·버튼 라벨이 잘리거나 의도와 다르게 고정 줄바꿈되지 않는지 확인합니다.
3. 가로 스크롤, viewport 밖의 고정 요소, 겹치는 CTA가 없는지 확인합니다.
4. 터치 대상의 간격과 키보드 포커스 이동이 시각 순서와 일치하는지 확인합니다.

- Figma의 고정 좌표를 그대로 옮기기보다 컨테이너 폭, 최대 폭, 여백, grid·flex 규칙으로 의도를 재현합니다.
- 장식 요소는 작은 화면에서 메시지·CTA를 방해하면 축소·숨김·재배치를 검토합니다. 핵심 정보와 조작 요소는 CSS만으로 사라지게 하지 않습니다.
- 앵커 내비게이션을 추가할 때는 target id가 한 번만 존재하고, sticky header에 가려지지 않는지 확인합니다.
