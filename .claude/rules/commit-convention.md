# 커밋 컨벤션

- 형식은 `<type>: <한국어 명사형 제목>`입니다.
- 허용 type은 `commitlint.config.mjs`가 단일 기준입니다. 이 문서에 목록을 따로 적지 않습니다.
- scope와 이슈 번호는 커밋 제목에 넣지 않습니다. 이슈 연결은 PR 본문에서 처리합니다.
- `Co-Authored-By`, `Generated by` 같은 AI 출처 문구를 넣지 않습니다.

## 제목 작성 기준

- `:` 앞에는 공백을 두지 않고, 뒤에는 공백 한 칸을 둡니다.
- 완료 보고가 아니라 변경 목적을 한국어 명사형으로 씁니다. 예: `feat: 공고 목록 필터 추가`, `fix: 지원서 임시저장 누락 수정`
- 제목에 파일명과 마침표를 넣지 않습니다. 50자 이내를 우선합니다.

## 커밋 나누기

- 커밋 하나에는 리뷰하고 되돌릴 수 있는 목적 하나만 둡니다.
- 기능 구현과 관련 없는 대량 포맷 변경은 별도 커밋으로 분리합니다.

## type 선택

| type               | 사용할 때                                   |
| ------------------ | ------------------------------------------- |
| `feat`             | 새로운 사용자 기능 또는 화면 동작           |
| `fix`              | 기존 동작, 레이아웃, 접근성의 오류 수정     |
| `design`           | UI·스타일·에셋 등 시각적 변경               |
| `refactor`         | 동작을 바꾸지 않는 구조 개선                |
| `style`            | 동작 영향 없는 포맷 정리                    |
| `docs`             | 문서와 작업 지침 변경                       |
| `test`             | 테스트 추가 또는 수정                       |
| `chore`            | 도구, 설정, 의존성 등 보조 작업             |
| `ci`               | GitHub Actions 등 CI 설정                   |
| `rename`, `remove` | 이름 변경 또는 삭제가 변경 목적 자체인 작업 |
| `revert`           | 이전 커밋 되돌리기                          |
