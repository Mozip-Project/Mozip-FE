# 코드 스타일

## 기본 형식

- TypeScript와 React 컴포넌트는 현재 ESLint·Prettier 규칙을 따릅니다. `src/` TypeScript 파일에는 타입 정보를 활용한 ESLint 권장 규칙도 적용됩니다.
- 세미콜론, 따옴표, 줄 길이, Tailwind class 정렬은 Prettier를 단일 기준으로 사용합니다. 수동 포맷 규칙을 추가하지 않습니다.
- import는 외부 패키지, `@/` alias, 상대 경로 순서로 두고, 같은 모듈의 type은 `import type` 또는 inline type import로 정리합니다.

## 네이밍과 타입

- 파일명과 폴더명은 kebab-case, React 컴포넌트와 타입은 PascalCase, 함수·변수는 camelCase를 사용합니다.
- 모듈 수준의 고정 설정값·제한값은 `UPPER_SNAKE_CASE`로 작성합니다. JSX 안에서 계산되는 값이나 단일 함수의 지역 값까지 기계적으로 대문자화하지 않습니다.
- 컴포넌트와 모듈 수준의 이름 있는 함수는 `function` 선언을 기본으로 합니다. 짧은 콜백과 배열 변환에는 화살표 함수를 사용합니다.
- 타입 전용 import는 `import type`을 사용합니다.
- 외부 입력의 형태를 모를 때는 `any` 대신 `unknown`으로 시작하고, 사용하는 경계에서 필요한 만큼 좁힙니다.
- 문자열 union이 여러 위치에서 반복되면 `as const` 배열에서 타입을 파생합니다. 값별 설정은 `Record`와 `satisfies`로 누락을 막습니다.

## JSX와 스타일

- 클래스는 Tailwind 유틸리티로 작성하고, 프로젝트에 없는 임의의 CSS-in-JS·인라인 style을 도입하지 않습니다.
- 섹션 내부의 반복 콘텐츠는 명시적인 타입을 둔 데이터 배열로 관리합니다.
- props와 상수의 이름은 디자인 용어보다 사용자와 도메인 의미를 우선합니다.
- JSX에서 긴 문자열 결합, 중첩 삼항, 복잡한 계산이 생기면 의미가 드러나는 지역 변수나 작은 함수로 분리합니다. 한 번만 쓰는 짧은 마크업까지 과도하게 추상화하지 않습니다.

## 상태와 제어 흐름

- boolean은 `is`, `has`, `can`, `should`처럼 상태가 읽히는 접두사로 시작합니다.
- 이벤트 prop은 `on`, 내부 이벤트 함수는 `handle`로 시작합니다. 부수 효과가 있는 유틸리티는 동작을 이름에 드러냅니다.
- 여러 조건을 판별할 때는 예외·종료 조건을 먼저 반환해 중첩을 줄입니다. 다만 분기를 함수로 쪼개는 편이 의도를 더 흐리면 현재 흐름을 유지합니다.
- 조건식이 여러 도메인 규칙 또는 연산을 합치면 결과의 의미가 드러나는 지역 변수로 분리합니다. 자명한 조건까지 과도하게 이름 붙이지 않습니다.
- 배열 렌더링의 key에는 데이터의 안정적인 식별자를 사용합니다. 순서는 고정이고 재정렬·삽입이 일어나지 않는 정적 콘텐츠가 아니라면 index를 key로 쓰지 않습니다.
- `as` 단언은 외부 입력의 검증 결과처럼 근거가 가까운 경우에만 사용합니다. 타입 오류를 숨기기 위한 이중 단언은 사용하지 않습니다.
- 주석은 코드가 하는 일을 반복하지 않고, 선택한 이유·제약·외부 근거만 남깁니다. 이름이나 주변 코드로 이미 드러나는 내용은 주석으로 다시 쓰지 않습니다.
- 남기는 주석은 1~~2줄로 짧게 쓰고, "~~한다/~~된다" 같은 문장형이 아니라 "~~ 사용", "~~ 방지", "~~ 처리"처럼 명사형으로 끝맺습니다.
- 개발 중 확인용 `console.log`는 남기지 않습니다. `console.warn`과 `console.error`도 사용자·운영 영향과 목적을 검토한 경우에만 사용합니다.
- App Router에서는 `next/router`, `next/document`를 import하지 않고 `next/navigation`, `layout.tsx`, metadata API를 사용합니다.
