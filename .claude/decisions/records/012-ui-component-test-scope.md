# 공용 UI 컴포넌트는 직접 연결한 접근성 계약만 테스트한다

- 상태: accepted
- 기록일: 2026-11-05

## 맥락

공용 UI 컴포넌트 9종을 추가하며 radix 동작(포커스 이동, Esc 닫기)과 `src/utils/`에서 이미 테스트한 계산까지 컴포넌트 테스트에서 다시 확인하고 있었습니다. 데이터 연동 이후에는 도메인 화면에서도 사용자 흐름 테스트를 쓰게 되어 같은 동작을 여러 층에서 중복 검증하게 됩니다.

## 결정

`src/components/ui/` 공용 컴포넌트 테스트에는 직접 연결한 `aria-*`·숨김 문구처럼 깨져도 화면에 드러나지 않는 접근성 계약만 둡니다.

- radix·브라우저가 보장하는 동작과 단순 표시는 테스트하지 않고 Storybook과 브라우저에서 확인합니다.
- 계산은 `src/utils/`로 분리해 그쪽에서 경계값까지 테스트합니다.
- 사용자 흐름은 데이터 연동 이후 도메인 화면 테스트에서 다룹니다.

## 근거

- 라이브러리가 보장하는 동작을 다시 테스트하면 유지 비용만 늘고 회귀를 잡지 못합니다.
- 레이아웃 값을 mock해야 하는 컴포넌트 테스트는 jsdom 한계로 깨지기 쉽고, 같은 계산은 util 테스트가 더 정확하게 검증합니다.

## 고려한 대안

- 인터랙티브 공용 컴포넌트마다 사용자 흐름·접근성 테스트 유지: 기존 규칙이었지만 radix 동작과 util 계산을 중복 검증합니다.
- 공용 컴포넌트 테스트를 모두 제거: 숨김 문구 결합처럼 화면에 드러나지 않는 회귀를 놓칩니다.

## 영향 범위

- `src/components/ui/__tests__/`
- `.claude/rules/testing.md`, `.claude/rules/component-guide.md`, `docs/TESTING.md`
- 기존 공용 컴포넌트 테스트(`tabs`, `toast` 등)는 아직 이 기준으로 정리하지 않았습니다.
