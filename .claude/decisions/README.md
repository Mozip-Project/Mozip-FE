# 결정 기록

여러 기능에 반복 영향을 주고, 이후 구현의 선택지를 실제로 제한하는 구조·라이브러리·디자인 토큰·콘텐츠 처리 규칙만 기록합니다.

- 단순 섹션 구현, 카피 오타, 개별 간격 조정, 단일 에셋 교체, 좁은 설정값 변경은 기록하지 않습니다.
- 구현이 한 작업 범위에만 영향을 주고 되돌리기 쉬우며, 다음 작업자가 반드시 따라야 할 규칙을 만들지 않으면 기록하지 않습니다. PR·커밋 설명 또는 코드 주석으로 충분한 내용도 제외합니다.
- 기록 전에는 다음을 모두 만족하는지 확인합니다: 여러 후속 작업에 영향을 주는가, 합리적인 대안 사이의 선택이 있었는가, 선택을 바꾸려면 여러 파일·사용처를 함께 검토해야 하는가.
- 새 문서는 `records/NNN-short-title.md` 형식으로 작성합니다.
- 기록에는 상태, 결정, 근거, 고려한 대안과 영향 범위를 짧게 남깁니다.
- 이전 결정을 바꿀 때는 기존 기록을 지우지 않고, 같은 문서에 변경 시점과 이유를 이어 씁니다.
- 상태는 `proposed`, `accepted`, `superseded`, `rejected` 중 하나로 기록합니다. `superseded`일 때는 대체 기록을 링크합니다.
- 한 기록에는 하나의 결정만 둡니다. 구현 과정, 회의 대화, 파일 목록을 장황하게 복제하지 않습니다.
