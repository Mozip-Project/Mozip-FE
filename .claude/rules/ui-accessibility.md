# UI와 접근성

공고 목록·상세, 지원서 작성, 서류·면접 평가, 운영진 관리 같은 기능 화면을 구현하거나 검토할 때의 화면 구조·반응형·접근성 기준입니다.

## 화면 구조

- `.claude/references/design-source.md`의 Figma 노드를 기준으로 정보 위계와 주요 동작의 위치를 유지합니다.
- 의미에 맞는 `header`, `main`, `nav`, `section`, `footer`, `form`, `table`, `button`, `a`를 사용합니다.
- 페이지마다 화면 목적이 드러나는 `h1` 하나를 두고, 하위 영역 제목은 순서가 이어지는 heading 계층으로 작성합니다. 시각 크기를 이유로 heading 레벨을 건너뛰지 않고, 장식 문구를 heading으로 만들지 않습니다.
- 페이지 이동은 `a`(`next/link`), 현재 화면의 동작은 `button`을 사용합니다.
- 외부 링크는 새 탭이 필요한 이유가 있을 때만 `target="_blank"`를 사용하고, 이동 결과를 예측할 수 있는 라벨을 제공합니다.

## 폼

- `input`, `textarea`, `select`에는 보이는 label을 연결합니다. 디자인상 label이 없으면 `aria-label` 등 접근 가능한 이름을 제공하고, placeholder만으로 대신하지 않습니다.
- 필수 항목은 시각 표시와 함께 `required` 또는 `aria-required`로 드러냅니다.
- 검증 오류는 해당 입력 가까이에 텍스트로 보여 주고, `aria-invalid`와 `aria-describedby`로 입력과 연결합니다.
- 제출에 실패하면 첫 번째 오류 입력으로 focus를 옮깁니다.
- 제출 중에는 중복 제출을 막고, 진행 중이라는 사실을 텍스트로 알립니다.

## 상태 표시

- 서버 데이터를 쓰는 영역은 로딩·에러·빈 상태를 구분해 보여 줍니다.
- 저장 완료처럼 화면 이동 없이 바뀌는 결과는 `role="status"`, 즉시 알려야 하는 오류는 `role="alert"`로 전달합니다.
- 지원 상태·평가 결과 같은 상태 표시는 색상만으로 구분하지 않고 텍스트를 함께 둡니다. 대비는 충분히 확보합니다.
- 사용할 수 없는 컨트롤은 이유를 주변 텍스트로 알릴 수 있는지 검토합니다.

## 상호작용

- 키보드 focus는 항상 보여야 하며, focus 순서는 화면의 읽기·조작 순서와 일치해야 합니다. 대체 스타일 없이 `outline-none`만 적용하지 않습니다.
- Dialog, Popover, Menu는 열릴 때 내부로 focus가 이동하고, Esc로 닫히며, 닫히면 연 요소로 focus가 돌아오는지 확인합니다.
- 메뉴, accordion, 탭처럼 상태가 있는 UI는 `aria-expanded`, `aria-selected`, `aria-current`로 열림 상태와 현재 항목을 드러냅니다.
- hover만으로 중요한 정보나 조작을 제공하지 않습니다. 키보드 focus와 터치 환경에서도 같은 목적을 달성할 수 있어야 합니다.
- 링크와 버튼은 이름만으로 목적을 알 수 있어야 합니다. 아이콘만 있는 버튼이나 "자세히 보기"처럼 반복되는 문구에는 대상을 포함한 접근 가능한 이름을 제공합니다.

## 이미지

- 장식 이미지는 빈 alt, 정보를 전달하는 이미지는 구체적인 alt를 제공합니다.
- 이미지 영역은 고정된 크기·비율 또는 `fill`과 올바른 `sizes`를 지정해 레이아웃 이동을 막습니다. 우선 로드는 첫 화면의 LCP 후보에만 적용합니다.

## 반응형

- 지원자·운영진 화면 모두 좁은 화면에서 가로 스크롤, 잘린 텍스트, 터치하기 어려운 컨트롤이 없어야 합니다.
- Figma의 고정 좌표를 그대로 옮기기보다 컨테이너 폭, 최대 폭, 여백, grid·flex 규칙으로 의도를 재현합니다.
- 공고 제목, 조직명처럼 길이를 예측할 수 없는 텍스트는 `min-w-0`과 줄바꿈 또는 말줄임 처리를 검토합니다.
- sticky 헤더나 하단 고정 버튼이 콘텐츠, focus된 입력, 오류 메시지를 가리지 않는지 확인합니다.
- 핵심 정보와 조작 요소는 작은 화면에서 CSS만으로 사라지게 하지 않습니다.

### 확인 순서

1. 작은 화면에서 내용이 한 열로 자연스럽게 읽히는지 확인합니다.
2. 제목·숫자·버튼 라벨이 잘리거나 의도와 다르게 줄바꿈되지 않는지 확인합니다.
3. 가로 스크롤, viewport 밖의 고정 요소, 겹치는 버튼이 없는지 확인합니다.
4. 터치 대상의 간격과 키보드 focus 이동이 시각 순서와 일치하는지 확인합니다.
