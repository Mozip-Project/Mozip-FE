# pr

PR 제목과 본문 초안을 만듭니다. 사용자가 명시하지 않으면 PR을 직접 생성하지 않습니다. 본문 형식은 `.github/PULL_REQUEST_TEMPLATE.md`를 우선합니다.

## 작업 흐름

1. `git status --short`, 현재 브랜치, `git log`, 대상 브랜치와의 diff를 확인합니다.
2. `.github/PULL_REQUEST_TEMPLATE.md`, `.claude/rules/git-workflow.md`, `.claude/rules/commit-convention.md`, `.claude/rules/verification.md`를 읽습니다.
3. 대상 브랜치는 항상 `main`으로 제안합니다.
4. `<type>/<issue-number>-<english-slug>` 형식의 브랜치에서는 type과 이슈 번호를 추출합니다.
5. 변경을 기능, 수정, 문서, 테스트, 설정, 자동화, 리팩터링으로 분류하고, 리뷰어에게 중요한 영향부터 정리합니다.
6. 템플릿의 상단 안내와 최상위 section 순서를 보존합니다. 실제로 실행한 검증만 체크합니다.
7. AI 지침, agent, skill, hook, workflow 자동화 변경이 큰 경우에만 [AI·자동화 PR 기준](references/ai-automation-pr.md)을 읽습니다.

`--append`가 있고 사용자가 기존 PR 본문을 제공한 경우에는 기존 내용을 다시 만들지 않고, 추가할 section 또는 bullet만 제안합니다.

## 제목 규칙

- 자동 정규화 대상 브랜치에서는 `[Feat] 제목`처럼 `[Type] <한국어 명사형 제목>`을 제안합니다.
- `Type`은 `Feat`, `Fix`, `Hotfix`, `Refactor`, `Test`, `Docs`, `Chore` 중 하나입니다.
- 자동 정규화 대상이 아닌 브랜치에서는 type을 추측해 덧붙이지 않습니다.
- 제목은 커밋 메시지보다 PR의 목적과 리뷰 범위를 설명하는 데 집중합니다.

## 본문 규칙

- `.github/PULL_REQUEST_TEMPLATE.md`의 최상위 section 이름과 순서를 그대로 사용합니다.
- 템플릿 전문을 이 스킬에 복제하지 않습니다. 템플릿이 바뀌어도 항상 현재 `.github/PULL_REQUEST_TEMPLATE.md`를 단일 기준으로 사용합니다.
- 이슈 자동 종료가 필요하면 `close #<번호>` 형식으로 작성하고, 이슈를 찾지 못하면 템플릿의 placeholder를 남기지 않고 `- 없음`으로 표시합니다.
- `📝 작업 내용`에는 파일 나열 대신 무엇을 왜 바꿨는지, 영향 범위와 리뷰 포인트를 작성합니다.
- 변경 규모가 크면 `📝 작업 내용` 안에서 `### 주요 변경사항`과 `### 세부 작업`으로 나누어 읽기 쉽게 작성할 수 있습니다.
- `✅ 체크사항`은 실행 근거가 있는 항목만 체크합니다. UI 변경, 새 라이브러리, 미실행 검증은 관련 section에 사실대로 남깁니다.
- 자동 생성 브랜치가 아닌 경우에도 연관 이슈, 검증, 리뷰 요구사항을 추측하지 않습니다.
- AI 출처 문구(`Co-Authored-By`, `Generated by`)를 넣지 않습니다.

## 출력 형식

- 제목은 `제목: [Type] 한국어 명사형 제목` 한 줄로 제안합니다.
- 본문은 사용자가 그대로 복사할 수 있도록 하나의 Markdown code block 안에 완전한 형태로 제공합니다. 본문을 여러 code block이나 설명 문단으로 나누지 않습니다.
- 템플릿에 없는 WIP, 검증, 주요 변경사항 같은 최상위 section을 임의로 추가하지 않습니다. 세부 설명은 템플릿의 기존 section 안에 넣습니다.
