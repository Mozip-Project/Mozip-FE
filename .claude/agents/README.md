# 에이전트 검증 하네스

프로젝트 에이전트는 구현을 대신하는 역할이 아니라, 메인 세션의 변경을 독립된 관점으로 점검하는 읽기 전용 검증 경계입니다. 역할이 겹칠 때는 더 많은 에이전트를 호출하기보다 변경 위험과 필요한 증거를 기준으로 선택합니다.

## 실행 계약

1. 메인 세션은 변경 범위, 확인할 사용자 결과, 사용할 근거(자료·명령)를 정합니다.
2. 선택된 에이전트는 자신의 지침과 필요한 project rule만 읽고, 작업 트리와 관련 diff를 확인합니다.
3. 에이전트는 파일을 수정하지 않으며, 사실·코드·렌더 결과에서 직접 확인한 내용과 추론을 구분합니다.
4. 결과는 `확인 범위`, `발견 사항`, `근거`, `미검증 공백` 순으로 반환합니다. 발견 사항에는 `파일:줄` 또는 확인한 화면·viewport를 포함합니다.
5. 메인 세션만 수정·재검증·최종 결론을 책임집니다. 근거가 부족하면 통과라고 표현하지 않고 `BLOCKED` 또는 검증 공백으로 남깁니다.

## 역할 선택

| 변경 또는 질문                                   | 우선 역할              | 필요할 때 함께 사용하는 역할 |
| ------------------------------------------------ | ---------------------- | ---------------------------- |
| App Router, layout, metadata, Server/Client 경계 | route-reviewer         | reviewer, verifier           |
| 반응형, 시맨틱, 폼, 모션, 접근성                 | accessibility-reviewer | verifier                     |
| Figma 화면 구현, 렌더 결과와 Figma의 비교        | visual-verifier        | accessibility-reviewer       |
| 버그 재현과 원인 추적                            | debugger               | verifier                     |
| 변경 완료 전 명령과 증거 확인                    | verifier               | 해당 전문 리뷰어             |
| 전체 diff의 실제 회귀 위험                       | reviewer               | 변경 성격에 맞는 전문 리뷰어 |

## 검증 종료 기준

- **PASS**: 필요한 근거와 검증 결과가 있고, 수정이 필요한 발견 사항이 없습니다.
- **NEEDS_REVISION**: 근거가 있는 결함 또는 접근성·사실성 불일치가 있습니다.
- **BLOCKED**: 렌더 화면, 권한, 제공 자료처럼 판정에 필요한 입력이 없습니다.

시각 검증은 브라우저 접근이 실제로 가능할 때만 PASS/NEEDS_REVISION을 판정합니다. 코드만 읽은 결과는 시각 검증을 대체하지 않습니다.
