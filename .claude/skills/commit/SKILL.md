# commit

커밋 메시지와 명령만 제안합니다. `git add`와 `git commit`은 직접 실행하지 않습니다. 사용자가 출력된 명령을 복사해 직접 실행합니다.

## 작업 흐름

1. `git status --short`로 수정·삭제·추가 파일과 stage 상태를 확인합니다.
2. `git diff`와 `git diff --staged`로 작업 트리와 stage 영역을 모두 확인합니다.
3. `.claude/rules/commit-convention.md`와 `commitlint.config.mjs`를 읽습니다.
4. 서로 독립적으로 되돌릴 수 있는 변경은 별도 커밋으로 나눕니다.
5. `git status --short`의 파일 전체 목록을 기준으로, 각 파일을 정확히 하나의 커밋에만 배정합니다.
6. 각 커밋의 파일 묶음, 메시지, 실행 명령을 함께 출력합니다.

## 출력 형식

```text
커밋 1: feat: 공고 목록 필터 추가
- src/app/(applicant)/page.tsx
- src/features/recruitment/components/recruitFilter.tsx
```

```bash
git add "src/app/(applicant)/page.tsx" src/features/recruitment/components/recruitFilter.tsx
git commit -m "feat: 공고 목록 필터 추가"
```

## 규칙

- 메시지 규칙은 `.claude/rules/commit-convention.md`, 허용 type은 `commitlint.config.mjs`를 따릅니다.
- AI 출처 문구(`Co-Authored-By`, `Generated by`)를 넣지 않습니다.
- 경로에 공백, 괄호, 대괄호 같은 셸 특수문자가 있으면 경로를 큰따옴표로 감쌉니다. route group(`(applicant)`), 동적 세그먼트(`[recruitmentId]`)가 해당됩니다.
- `git add`에는 현재 존재하는 경로만 넣습니다. 추측한 경로를 넣지 않습니다.
- 검증하지 않은 변경이 있으면 커밋 전 확인 항목을 따로 표시합니다.
