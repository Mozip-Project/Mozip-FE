# 인증 토큰은 httpOnly 쿠키

- 상태: accepted
- 기록일: 2026-10-15

## 맥락

토큰 저장 위치(쿠키·메모리·localStorage)를 백엔드와 함께 정해야 했습니다.

## 결정

백엔드가 인증 토큰을 httpOnly 쿠키로 발급하고, 프론트엔드 코드는 토큰을 직접 읽거나 저장하지 않습니다.

## 근거

- JS에서 토큰에 접근할 수 없어 XSS로 인한 토큰 탈취를 막습니다.
- Server Component와 `proxy.ts`에서도 쿠키로 로그인 여부를 판단할 수 있습니다.

## 고려한 대안

- localStorage: XSS에 노출됩니다.
- 메모리 + refresh 쿠키: 새로고침 시 로그인 상태를 바로 알 수 없고 서버에서 판단하기 어렵습니다.

## 영향 범위

- 공용 API 클라이언트, 로그인 흐름, 배포 환경

## 검증 또는 재검토 조건

- FE와 BE가 같은 사이트(서브도메인)로 배포되지 않으면 Safari 등에서 쿠키가 차단됩니다. 로컬에서는 드러나지 않으므로 배포 환경에서 확인합니다.
- 같은 사이트 배포가 어려우면 `next.config`의 `rewrites`로 API를 중계하는 방안을 검토합니다.
- 계정 구분 방식은 아직 정하지 않았습니다.
